## 5. Information architecture

### 5.1 Screen inventory

| # | Screen | Route | Presentation | One purpose | Primary action |
|---|---|---|---|---|---|
| 00 | Onboarding | `/onboarding` | Replaces the app until finished | Explain the product, first launch only | **Continue**, then **Get Started** |
| 01 | Home | `/` (tab) | Tab root | Ask for three picks | **Discover** |
| 02 | Location | `/location` | Native form sheet | Set where to search | **Gamitin ito** [Use this] |
| 03 | Results | `/results` | Pushed, tab bar hidden | Choose one of three | Tap a pick |
| 04 | Place details | `/place/[id]` | Pushed, tab bar hidden | Confirm and go | **Directions** |
| 05 | Saved | `/saved` (tab) | Tab root | Return to kept places | Tap a place |
| 06 | Settings | `/settings` (tab) | Tab root | Change defaults and privacy | (none; each row acts on its own) |
| 07 | Directions | `/directions/[id]` | Pushed, tab bar hidden | See how to get there | (none; choose a travel mode, or open Google Maps) |

The brief calls screen 06 "Profile / Settings". With no account there is no profile, and a "Profile" tab suggests sign-in. Naming it **Settings** sets the right expectation. Rename it if accounts arrive later.

### 5.2 What each screen must show, in priority order

The order below is the visual order. If space runs out on a small phone, the lowest items scroll; the top items and the primary action never do.

| Screen | Priority 1 | Priority 2 | Priority 3 | Leave out |
|---|---|---|---|---|
| Discover | Activity + budget choices, primary action | Location line | Greeting, headline | Feeds, promos, "trending" lists |
| Location | Use current location / search field | Radius | Recent areas | A map (not needed to choose an area) |
| Results | The three picks with labels | Reason lines | Shuffle / change | Filters, sort, maps |
| Place details | Open status, distance, cost | Address, rating, why picked | Description, more photos | Reviews feed, rating breakdown bars (data not available, see §7.4) |
| Saved | Saved places | Remove + undo | (empty state) | Folders, lists, notes |
| Settings | Defaults | Privacy | About | Account sections |
| Directions | Map, travel time, distance | Travel mode, written steps | Google Maps link, credit | Live navigation, traffic, jeepney and bus routes (data not available) |

### 5.3 Interaction flows

**Main flow (returning user, location remembered)**
```
Discover ──tap Nugagawen?──▶ Results ──tap pick──▶ Place details ──Directions──▶ Directions
   ▲                            │  ▲                    │
   └──── Baguhin [Change] ──────┘  └── Iba naman        └── Save ──▶ (appears in Saved)
                                       [Something else]
```

**First run (no location yet)**
```
Discover ──tap Nugagawen?──▶ Location sheet ──Gamitin ito──▶ Results
                              (asks permission only if the user taps
                               "Use my current location")
```

**Location permission denied**
```
Location sheet ──tap "Use current location"──▶ OS prompt ──Deny──▶
  inline message + "Buksan ang Settings" [Open Settings] button
  search field stays available ──▶ pick an area ──▶ Gamitin ito
```

**Few or no results**
```
Results (0–2 picks) ──"Palawakin sa 5 km" [Widen to 5 km]──▶ Results (re-search)
                    └─"Baguhin" [Change]──▶ Discover (selections kept)
```

**Save and undo**
```
Place details ──Save──▶ button shows "Saved" + toast "Na-save" [Saved]
Saved tab ──remove──▶ row disappears + toast "Inalis. [Ibalik]" [Removed. Undo]
```

**Offline**
```
Any network step fails ──▶ inline error with "Subukan ulit" [Try again]
Saved tab still lists places (details need a connection)
```

## 6. Navigation structure

```
Root Stack
├── (tabs)                    platform tab bar, labels always visible
│   ├── Hanap  [Find]          /            Discover
│   ├── Saved                  /saved
│   └── Settings               /settings
├── location                   /location    form sheet, swipe down to dismiss
├── results                    /results     push, tab bar hidden
└── place/[id]                 /place/:id   push, tab bar hidden
```

**Why Discover is inside the tabs (decision D4).** The brief's suggested file layout puts Home outside the tab group. That would mean the tab bar disappears on the main screen, or the Home screen has no tab bar route to return to. Putting Discover in the tabs keeps one predictable rule: *tabs are places you live, pushed screens are steps in a task.*

**Rules**
- The tab bar uses the platform's own tab bar (not a custom floating one). Icons always have text labels.
- Results and Place details are pushed on top and hide the tab bar. The task has focus, and back always returns to where you came from.
- Back from Results returns to Discover with selections kept. Android's system back does the same thing.
- Location is a sheet because it is a short side-task of Discover. Dismissing it without confirming changes nothing.
- No screen is more than two levels deep.
- Headers are the platform's stack headers, configured rather than rebuilt, so back-swipe and accessibility work for free.

## 7. Screen-by-screen UX

**Wireframe legend:** `[i:name]` = icon, `( )` = control, `▓` = photo, `░` = loading skeleton, `│ │` boxes = tappable control boundaries. Width ≈ 390 pt; 24 pt side padding.

| Copy | English gloss |
|---|---|
| Magandang umaga / hapon / gabi. | Good morning / afternoon / evening. (time-based) |
| Wala pang plano? | No plans yet? |
| Tara, hanapan kita. | Come on, I'll find you something. |

| Ano'ng gusto mo? | What do you feel like? |
| Kain / Gala / Kahit ano | Eat / Go out / Anything |
| Magkano ang budget bawat tao? | How much is the budget per person? |
| Tipid / Sakto / Sosyal | Thrifty / Just right / Fancy |

**Behaviour**
- Defaults: Kahit ano + Sakto on first run; afterwards the last-used values.
- Each selector is a single-choice group. Exactly one option is always selected, so the primary action is never disabled.
- The pinned action bar keeps **Nugagawen?** in the thumb zone on every phone size.
- Changing a selection gives instant visual feedback (on press, not release) and a light selection haptic.

**Small phones and large text**
- Tiles keep three across while every label and amount fits on one line. Side padding is 12 pt, dropping to 8 pt when that is what it takes (360 pt Android phones). When even 8 pt isn't enough (320 pt phones, or system text above about 120% on a 390 pt phone), the tiles stack into full-width rows. This is a layout switch, never smaller text. Thresholds were measured in the Phase 5 mockups: the widest label, "₱250–600", needs 74.4 pt.
- Greeting and headline wrap; nothing truncates.

**States**

| State | What the user sees |
|---|---|
| No location yet (first run) | Location row reads "Saan ka?" [Where are you?] with "Pumili" [Choose]. The primary action opens the Location sheet, then continues to Results. |
| Location set | As wireframe. |
| Locating (GPS refresh) | Location row keeps the last known area with a small "Ina-update…" [Updating…] line; never blocks the primary action. |

**Typing state:** "Recent" is replaced by suggestion rows (area name bold, city/province secondary). Results update as the user types, with a short debounce so we don't spend a request per keystroke. **States**

| State | Treatment |
|---|---|
| Permission never asked | Row as wireframe. Tapping it triggers the OS prompt. |
| Locating | Row shows "Hinahanap ka…" [Finding you…] with a small inline indicator. Rest of the sheet stays usable. |
| Located | "Napili" line updates to the detected area. |

| GPS timeout / error | "Hindi ka namin mahanap ngayon. Subukan ulit o maghanap sa ibaba." [We can't find you right now. Try again or search below.] |
| No search matches | "Walang tumugma sa '{query}'. Subukan ang pangalan ng lungsod o barangay." [Nothing matched. Try a city or barangay name.] |
| Offline | "Walang internet. Kailangan ito para maghanap ng lugar." [No internet. Needed to search for places.] + "Subukan ulit" [Try again]. |

**Reason lines** are assembled only from real attributes (rating, review count, distance, open status, category difference, price fit). Examples and their triggers:

| Pick | Example | Built from |
|---|---|---|
| Safe choice | "Mataas ang rating at malapit lang." [Highly rated and close by.] | rating ≥ 4.2 and distance in nearest third |
| Surprise me | "Iba sa karaniwan mong pinupuntahan." [Different from your usual.] | category differs from Safe choice |
| Hidden gem | "Kaunti pa lang ang nakakaalam." [Not many people know it yet.] | high rating, low review count |
| Any | "Bukas pa hanggang 10 PM." [Open until 10 PM.] | opening hours |

**Interactions**
- The whole Safe choice block (photo and text) and each alternate row are single tap targets that open Place details.
- **Iba naman** swaps the three picks in place: content cross-fades, layout doesn't jump, no entrance animation replays. A screen-reader announcement reads "Bagong tatlong pagpipilian" [Three new options].
- **Iba naman** and **Baguhin** come after the third pick, not in a pinned bar. They're only needed once the picks have been read, and unpinning them lets all three picks' labels and names fit on a 390 × 844 screen (measured in Phase 5).
- **Baguhin** returns to Discover with selections kept. **Simula ulit** resets selections to defaults and returns to Discover. It's reversible, so no confirmation dialog.

**Decisions**
- **No rating-breakdown bars** (the Communication/Cleanliness bars in the reference image). The place data source doesn't provide them, and we never fabricate them.
- **Open status is text plus an icon**, not a green or red dot alone. Values: "Bukas ngayon" [Open now], "Sarado ngayon. Bubukas {time}." [Closed now. Opens {time}.], "Walang info sa oras" [No hours info].
- **Directions** opens the directions screen (screen 07). A small map above "Why this?" opens it too. The action keeps the same name everywhere.
- **Save** toggles to "Saved" with a filled icon, and a toast says "Na-save" [Saved]. Toggling off says "Inalis sa Saved" [Removed from Saved] with "Ibalik" [Undo].
- Header buttons sit on the photo, so they get a solid round background for contrast. No text sits directly on photos without a scrim.

**States:** loading (skeleton: photo block + text lines), place no longer available ("Hindi na available ang lugar na ito." [This place is no longer available.] + back), offline (cached basics if opened from Results, retry for the rest).

### 7.8 Screen 00: Onboarding

**Purpose:** say what Nugagawen does before the person meets the interface. Added in v1.2.

Three slides, each with its own illustration on its own tint: Discover ("Not sure where to go?"), Choose ("Set your budget and location."), Decide ("Get three recommendations."). Controls: Skip (not on the last slide), Back (not on the first), Continue, Get Started, and a three-step progress indicator. The first slide also offers English or Filipino, so the rest can be read in the person's language.

- **Appears once.** Finishing or skipping is saved on the phone (`src/state/first-run.tsx`). Settings > Guides can replay it.
- **Asks for nothing.** Location permission stays where it was: only when the person taps "Use my current location".
- **Can't flash or be escaped by accident.** The router's `Stack.Protected` makes the app's screens exist only after onboarding, so Home never shows first and Back can't leave it.

### 7.9 The Home guide

**Purpose:** teach the real interface. Separate from onboarding, and saved separately. Added in v1.2.

After onboarding, Home offers a walkthrough ("Want a quick tour?"). Declining counts as done. Settings > Guides can replay it.

| Step | Highlights | Says |
|---|---|---|
| 1 | Activity selector | Start by choosing what you want to do. Pick Kain, Gala, or Kahit Ano. |
| 2 | Budget selector | Choose a budget that feels right for you. |
| 3 | Location picker | Discover places near your current location or choose another area. |
| 4 | Discover button | Tap Discover to find three recommendations based on your preferences. |
| 5 | Nothing (see below) | Compare your choices, explore place details, save your favorites, or get directions. |

- **One element at a time.** The page dims around it, and the page scrolls to bring it into view.
- **Not a wall.** The highlighted element stays usable, so people can try it while reading, and the tab bar stays usable too.
- **Step 5 has nothing to highlight,** because results don't exist yet on Home. It shows the three-picks illustration instead. Any step whose element is missing does the same, rather than breaking.
- **Keyboard and screen readers.** Each step is announced, focus moves to Next, and Escape leaves the guide on web.
